## 2. Architecture & Design Decisions

- **`Drone` Entity State Encapsulation:**
  - `Drone` tracks `current_zone`, `target_zone`, and `steps_remaining`.
  - Implemented `@property is_in_transit -> bool` for clear transit query checks.
  - Implemented `__str__` returning `D{id}` to align directly with 42 simulation output format (`D1-hubA`).
  - Added `__eq__` and `__hash__` keyed on `self.id` to allow fast $O(1)$ lookups and removal inside `Zone.drones: set[Drone]`.

- **`Connection` Entity and Bidirectional Equivalence:**
  - Represents an undirected edge linking `zone_a` and `zone_b`.
  - Implemented `__eq__` using set equality `{zone_a.name, zone_b.name} == {other.zone_a.name, other.zone_b.name}`.
  - Implemented `__hash__` using `frozenset({self.zone_a.name, self.zone_b.name})` ensuring that connection `(A, B)` equals `(B, A)` and hashes identically, preventing accidental duplicate edges.
  - Added utility methods: `connects(zone)` and `get_other_endpoint(current)` with strict exception handling.

## 5. Challenges, Blockers & Lessons Learned
- **`__hash__` and Inmutability (`frozenset`):** Standard Python `set` is mutable and unhashable; using `frozenset` allows hashing unordered collections cleanly.
- **Return Type Precision:** `get_other_endpoint` always returns a `Zone` or raises an exception, so its return type is strictly `Zone` rather than `Zone | None`.
